# TasKanLine для агента

TasKanLine — трекер задач: **пространство** (`acme`) → **команды** с ключом (`ENG`) →
**проекты** → **задачи** с ключом `ENG-142`. У каждой команды **свои статусы**; у статуса есть
тип: `backlog`, `unstarted`, `started`, `completed`, `canceled`. Приоритеты: `urgent`, `high`,
`medium`, `low`, `none`. **View** — сохранённый срез задач с фильтрами.

Агент работает **от имени владельца токена** и видит ровно то, что видит этот человек. Задачу,
которую не видно, API называет «не найдена» — это не повод искать обход.

## 1. Выбери канал

1. **MCP.** Если среди инструментов есть `search_tasks`, `list_teams`, `get_task` (часто с
   префиксом `mcp__taskanline__`) — работай через них. Справочник:
   [references/mcp.md](references/mcp.md).
2. **CLI.** Иначе проверь `tkl --version`. Если есть — работай через `tkl` в shell. Справочник
   команд и языка фильтров: [references/cli.md](references/cli.md).
3. **Ничего нет** — установи CLI (нужен [uv](https://docs.astral.sh/uv/)):

   ```bash
   uv tool install "taskanline-cli @ git+https://github.com/yerza06/taskanline#subdirectory=cli"
   ```

   Из клона репозитория — `uv tool install ./cli`. MCP-сервер ставится так же, с
   `#subdirectory=mcp` (или `./mcp`); как подключить его к клиенту — в
   [references/mcp.md](references/mcp.md#подключение).

### Доступ

`tkl auth status` (exit 0 — всё настроено) покажет пользователя, адрес API и права токена:
`read` или `read,write`. MCP берёт токен из того же конфига `~/.config/taskanline/config.toml`.

Если токена нет — **не выдумывай и не ищи его по диску**. Попроси человека выпустить токен в
веб-клиенте (меню профиля → «Токены доступа»; «Только чтение», если менять ничего не нужно) и
выполнить вход **самому**, чтобы токен не оказался в переписке:

```bash
tkl auth login --token tkl_… --api-url https://<адрес API>   # адрес, где отвечает /api/v1
tkl config set workspace <slug>                               # пространство по умолчанию
tkl config set team <KEY>                                     # команда по умолчанию
```

В Claude Code человек может набрать это с префиксом `!` прямо в диалоге. В CI и других
неинтерактивных средах вместо конфига — переменные `TKL_API_URL`, `TKL_TOKEN`, `TKL_WORKSPACE`,
`TKL_TEAM`.

## 2. Правила, которые нельзя нарушать

- **Статусы и метки не угадывай.** Перед сменой статуса или созданием задачи узнай названия:
  `list_teams` / `tkl team states ENG`, метки — `tkl label list`. Ошибка `state_not_found`
  перечисляет допустимые статусы — бери оттуда, а не придумывай похожий.
- **Сначала прочитай, потом действуй.** Перед работой над задачей и перед пересказом —
  полная карточка (`get_task` / `tkl task show KEY`): в списках описание обрезано.
- **Пиши, только когда просили.** Создание, смена статуса, назначение, комментарий — по прямой
  просьбе или после подтверждения. Несколько задач сразу (разбивка на подзадачи, импорт плана) —
  сначала покажи список и дождись «да».
- **Удаление — только по явной просьбе** и только CLI: `tkl task delete KEY` (мягкое, вернуть —
  `tkl task restore KEY`). В MCP удаления нет намеренно.
- **Не повторяй создание «на всякий случай».** `tkl task create` идемпотентен при сетевом
  сбое внутри одного вызова, но второй вызов — это вторая задача. Если не уверен, создалась ли
  задача, сначала поищи её по заголовку (`title~…` / `query`).
- **Токен «только чтение»** (`403 insufficient_scope`, exit 3) — не обходи: скажи человеку, что
  для записи нужен токен «Чтение и запись».
- **Не утверждай того, чего не видел в ответе.** Ключ созданной задачи и новый статус бери из
  вывода команды — команды изменения печатают задачу после изменения.

## 3. Типовые сценарии

Ниже — CLI; в MCP то же самое делают инструменты из скобок.

**Что у меня в работе / что делать дальше** (`search_tasks`, `run_view`):

```bash
tkl task list -f "assignee:me state-type:started" --all-teams
tkl task list -f "assignee:me state-type:unstarted" --sort priority --limit 5 --all-teams
tkl view list                 # если человек говорит о своём срезе: «мои баги», «спринт»
tkl view run "Незакрытые баги"
```

**Взять задачу в работу** (`get_task` → `update_task_state`, `assign_task`):

```bash
tkl task show ENG-14
tkl team states ENG                       # как называется статус «в работе» именно здесь
tkl task assign ENG-14 me
tkl task state ENG-14 "In Progress"
```

**Отчитаться и закрыть** (`comment_task` → `update_task_state`):

```bash
tkl task comment ENG-14 -m "Готово в PR #218: кэш аватаров на 24 часа, тесты в tests/test_avatars.py"
tkl task close ENG-14                     # первый статус типа completed; --canceled — отменить
```

Комментарий — Markdown: что сделано, где (PR, коммит, файлы), что осталось. `@email` в тексте
уведомит человека. Длинный текст — из stdin: `git log -1 --format=%B | tkl task comment ENG-14 -`.

**Завести задачу** (`list_teams` → `create_task`):

```bash
tkl task create --team ENG --title "Кэшировать аватары" --priority medium \
  --label feature --assignee me -d @description.md
```

Подзадача — `--parent ENG-1`; в проект — `--project "Мобильное приложение"` (команда берётся из
проекта). Метка должна существовать: несуществующая — ошибка, а не создание.

**Разбить задачу на подзадачи** (MCP-промпт `breakdown_task`): прочитай карточку, предложи
список подзадач человеку, после подтверждения создай каждую с `--parent`.

**Связи**: `tkl task link ENG-14 --blocked-by ENG-3` (`link_tasks`, тип `blocked_by`); также
`--blocks`, `--relates-to`, `--duplicates`.

**Сводка для стендапа или по проекту** (MCP-промпты `standup`, `project_status`):

```bash
tkl task list -f "team:ENG updated:>=@today-1d" --sort -updated
tkl task list -f "project:\"Мобильное приложение\"" --all-teams
```

## 4. Как читать ответы CLI

- Когда stdout не терминал (а у агента это так), `tkl` **сам выводит JSON**. `--json` делает то
  же принудительно, `-q` — только ключи по одному на строку: `tkl -q task list -f "label:bug"`.
- В stdout — только данные; сообщения — в stderr.
- Код выхода говорит, что делать:

  | Код | Что случилось | Что делать |
  |---|---|---|
  | 0 | успех | |
  | 1 | неверный вызов: опция, фильтр, конфиг | прочитать сообщение, поправить команду |
  | 2 | ошибка API | повторить с `-v`, сообщить человеку |
  | 3 | нет прав: токен отозван, только чтение, роль | `tkl auth status`; попросить нужный токен |
  | 4 | не найдено (или не видно) | проверить ключ, команду, пространство |
  | 5 | конфликт | перечитать объект и повторить |
  | 6 | лимит запросов | подождать и повторить |
  | 7 | сервер недоступен | проверить `--api-url`; повторять бессмысленно |

- Ошибка печатается как `Ошибка [code]: текст` — ветвись по `code`, а не по тексту.
- Список постраничный: при `has_more: true` следующая страница — `--cursor <next_cursor>`.

## 5. Ссылки на задачу для человека

Поле `url` в выводе CLI и MCP сейчас имеет вид `<web_url>/ENG-14` и в браузере задачу не
открывает. Рабочая ссылка: `<адрес веб-клиента>/w/<slug пространства>/task/ENG-14`. Если адрес
веб-клиента неизвестен — называй просто ключ `ENG-14`.
