# 5. MCP-сервер `tkl-mcp`

`tkl-mcp` даёт ИИ-ассистенту — Claude Code, Claude Desktop, claude.ai, ChatGPT и любому другому
клиенту [Model Context Protocol](https://modelcontextprotocol.io) — инструменты трекера прямо в
диалоге. Попросите «покажи мои незакрытые баги» или «заведи задачи по этому плану», и модель
сама вызовет `search_tasks` или `create_task`.

Сервер работает **от имени владельца токена**, с его правами: видит ровно то, что видит этот
человек в веб-клиенте, и ни задачей больше.

## Установка и токен

```bash
uv tool install ./mcp      # бинарь tkl-mcp
```

Токен и адрес API сервер берёт из того же конфига, что и [CLI](04-cli.md): если вы уже
выполнили `tkl auth login`, сервер готов. Иначе — флагами `--token`, `--api-url` или
переменными `TKL_TOKEN`, `TKL_API_URL`.

Какой токен выпустить ([как](02-client.md#токены-доступа)):

| Задача ассистента | Права токена | Флаг сервера |
|---|---|---|
| отвечать на вопросы, делать сводки | **только чтение** | `--read-only` |
| заводить задачи, менять статусы, комментировать | **чтение и запись** | — |

С `--read-only` инструменты записи исчезают из каталога — модель не будет и пытаться. А токен
«только чтение» не даст ничего изменить, даже если флаг забыли: сервер ответит
`403 insufficient_scope`. Ставьте оба.

## Подключение

### Claude Code

```bash
claude mcp add taskanline -- tkl-mcp
# только чтение и одно пространство:
claude mcp add taskanline -- tkl-mcp --read-only --workspace acme
```

Или файлом `.mcp.json` в корне проекта — тогда сервер подключится у всех, кто работает с
репозиторием (токен у каждого свой, в его `~/.config/taskanline/`):

```json
{
  "mcpServers": {
    "taskanline": { "command": "tkl-mcp", "args": ["--workspace", "acme"] }
  }
}
```

### Claude Desktop

Settings → Developer → Edit Config, файл `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "taskanline": { "command": "tkl-mcp", "args": ["--profile", "work"] }
  }
}
```

Если Desktop не находит `tkl-mcp`, укажите полный путь: `"command": "/home/anna/.local/bin/tkl-mcp"`
(`which tkl-mcp` подскажет).

### Без установки, из репозитория

```json
{
  "mcpServers": {
    "taskanline": {
      "command": "uv",
      "args": ["run", "--directory", "/path/to/TasKanLine2", "tkl-mcp", "--read-only"]
    }
  }
}
```

### Удалённо: claude.ai, ChatGPT и другие веб-клиенты

Веб-клиенты не запускают процессы у вас на машине — им нужен сервер по HTTPS:

```bash
tkl-mcp --transport http --host 127.0.0.1 --port 8765 \
  --api-url https://tasks.acme.example --allowed-host mcp.acme.example
```

Поставьте перед ним HTTPS-прокси (nginx, Caddy) на `mcp.acme.example`. Клиент подключается к
`https://mcp.acme.example/mcp` и передаёт **свой** токен заголовком
`Authorization: Bearer tkl_…`. В HTTP-режиме сервер обслуживает многих людей сразу и не берёт
токен из процесса или конфига — только из заголовка запроса, — так что каждый работает со своими
правами.

`--allowed-host` (можно повторять) — какие значения заголовка `Host` принимать за прокси; без
него запросы на внешнее имя отклоняются (защита от DNS rebinding).

## Флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--transport stdio\|http` | `stdio` | stdio — для локальных клиентов, http — для удалённых |
| `--api-url URL` | `TKL_API_URL` или профиль | адрес API TasKanLine |
| `--token T` | `TKL_TOKEN` или профиль | токен (только для stdio) |
| `--profile P` | профиль по умолчанию | профиль общего с `tkl` конфига |
| `--read-only` | выкл. | убрать инструменты записи |
| `--workspace SLUG` | все доступные | показывать только одно пространство |
| `--max-items N` | 50 | потолок длины списков в ответах (не больше 50) |
| `--host`, `--port` | `127.0.0.1`, `8765` | HTTP: где слушать |
| `--allowed-host H` | — | HTTP: допустимый `Host` за прокси |

## Инструменты

Описание каждого инструмента — это подсказка для модели: когда его выбирать. Поэтому модель,
например, сначала смотрит статусы команды, а не угадывает их названия.

### Чтение

| Инструмент | Что делает |
|---|---|
| `list_workspaces` | пространства и ваша роль в каждом; нужен, только если их несколько |
| `list_teams` | команды с ключами и **их статусами** — вызывается перед созданием задач и сменой статусов |
| `list_projects` | проекты команды: имена, статусы, сроки |
| `search_tasks` | главный поиск: команда, исполнитель, тип статуса, метки, приоритет, срок, текст. Без фильтров — только открытые задачи; описание обрезано до 200 символов |
| `get_task` | полная карточка: описание целиком, связи, по запросу — последние комментарии, история, подзадачи |
| `list_views` | сохранённые views с фильтрами словами |
| `run_view` | выполнить view; `@me` в фильтрах — это владелец токена |

### Запись (нет в `--read-only`)

| Инструмент | Что делает |
|---|---|
| `create_task` | создать задачу; возвращает ключ и ссылку |
| `update_task` | изменить переданные поля; очистить поле — перечислить его в `clear` |
| `assign_task` | назначить или снять исполнителя |
| `update_task_state` | сменить статус по имени |
| `comment_task` | комментарий; `@email` в тексте уведомит человека |
| `link_tasks` | связь: блокирует, заблокирована, связана, дублирует |

Удаления задач среди инструментов нет намеренно: удалить можно в веб-клиенте или CLI.

### Ресурсы

Клиенты, которые умеют прикреплять ресурсы к диалогу, видят их по адресам:

| Адрес | Что внутри |
|---|---|
| `taskanline://workspace/{slug}` | обзор пространства: команды, открытые задачи по командам |
| `taskanline://team/{key}` | команда: статусы, проекты, метки, участники |
| `taskanline://project/{id}` | проект: описание, сроки, задачи по типам статусов |
| `taskanline://task/{key}` | задача в Markdown: поля, описание, последние комментарии |

### Готовые промпты

| Промпт | Аргументы | Для чего |
|---|---|---|
| `breakdown_task` | `key`, `max_subtasks` | разобрать задачу и предложить подзадачи |
| `project_status` | `project` | сводка по проекту |
| `whats_next` | `team`, `assignee` | за что взяться дальше |
| `standup` | `team`, `since` | сводка изменений для стендапа |

В Claude Code они доступны как команды `/mcp__taskanline__standup` и т. п.

## Как это выглядит

Ответ `search_tasks` с фильтром «исполнитель — я» на тестовом пространстве Acme (сокращён):

```json
{"tasks": [
  {"key": "ENG-1", "title": "Вход через Apple ID падает на iOS 18",
   "state": "In Progress", "state_type": "started", "assignee": "anna@acme.example",
   "priority": "urgent", "due_date": "2026-10-14", "labels": ["bug"],
   "project": "Мобильное приложение",
   "description": "После обновления до iOS 18 вход через Apple ID завершается ошибкой `invalid_grant`.\n\n**Шаги:** …"},
  {"key": "DES-3", "title": "Аудит доступности форм", "state": "Backlog", …}
]}
```

Ошибка возвращается модели текстом, по которому она может исправиться сама:

```
update_task_state(key="ENG-1", state="Ревью")
→ Статус «Ревью» не существует в команде ENG. Доступные: Backlog, Todo, In Progress, Done, Canceled.
```

Примеры просьб:

- «Что у меня в работе в ENG?» → `search_tasks(assignee="me", state_type="started", team="ENG")`
- «Открой view „Незакрытые баги“» → `list_views`, затем `run_view`
- «Разбей ENG-1 на подзадачи и заведи их» → `get_task`, `list_teams`, несколько `create_task` с
  `parent="ENG-1"` — модель сначала покажет список и спросит подтверждения
- «Отметь ENG-14 сделанной и напиши, что исправлено в PR #218» → `update_task_state`,
  `comment_task`

## Безопасность

- Один токен — один агент: выпускайте отдельный токен каждому ассистенту и машине, с понятным
  именем. Отозвать один можно, не трогая остальных.
- Где хватает чтения — токен `read` и `--read-only`.
- `--workspace` прячет от модели остальные пространства, если вы состоите в нескольких.
- Заблокированный в админке человек теряет и токены: его агенты перестают работать сразу.
- Всё, что агент сделал, видно в истории задачи: комментарии и изменения записываются от
  владельца токена, а в данных комментария сохраняется, каким токеном он оставлен.
