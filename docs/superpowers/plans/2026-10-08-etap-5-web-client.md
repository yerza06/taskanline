# Этап 5. Веб-клиент — Implementation Plan

> **Для исполнителя:** реализовывать задача за задачей, по TDD. Шаги отмечены чекбоксами (`- [ ]`).

**Goal:** полноценный интерфейс для человека поверх API этапов 2–4: оболочка с workspace и
боковым меню, список и доска задач с перетаскиванием (мышь и клавиатура), карточка задачи,
быстрое создание, конструктор фильтров и views, участники и приглашения, настройки команды,
уведомления, горячие клавиши. Готово, когда сценарии А–В проходят в Playwright.

**Architecture:** маршруты под `/_authed/w/$workspace/…` (slug в адресе — ссылку на задачу или
view можно переслать). Данные — TanStack Query, хуки в `features/<домен>/api`. Списки и доска
идут через `POST /views/query` (несохранённый view) и `GET /views/{id}/tasks`: у экрана один
язык фильтров с сохранёнными views. Фильтры, сортировка, группировка и вид живут в
типизированных search-параметрах TanStack Router. UI-мелочи, переживающие размонтирование
(открытое меню на телефоне, окно быстрого создания), — Zustand. Перетаскивание — dnd-kit,
перестановка — `POST /tasks/{id}/move` с оптимистичным обновлением кэша и откатом.

**Spec:** `…-architecture.md` (§4), `…-roadmap.md` («Этап 5»), `…-vision.md` (сценарии А–В),
`…-data-model.md` (§4 — грамматика фильтров).

## Решения сверх спеки (внести в спеки в последней задаче)

1. **Адреса:** `/w/$workspace` — пространство, `…/team/$key` — задачи команды (`?layout=board`
   — доска), `…/project/$projectId`, `…/view/$viewId`, `…/task/$key`, `…/inbox`, `…/members`,
   `…/team/$key/settings`. `/` ведёт в первое пространство, без пространств — на `/onboarding`.
2. **Карточка задачи — отдельная страница**, а не боковая панель: у неё свой адрес, её можно
   переслать, и на телефоне она не теснит список.
3. **Markdown описания и комментариев рендерится `react-markdown` без сырого HTML** — XSS через
   описание задачи исключён по конструкции.
4. **Playwright гоняет сценарии против настоящего бэкенда** на отдельной базе
   `taskanline_e2e`: схема пересоздаётся миграциями перед прогоном.

Добавлено по ходу реализации:

5. **Доска — колонки любой группировки** (сценарий В — доска по приоритету); между колонками
   переносится только при группировке по статусу.
6. **Цвет статусов и меток не показывается** — палитра чёрно-белая; новым ставится `#808080`.
7. **После входа, регистрации и принятия приглашения — `/`**, а не профиль: корень сам ведёт в
   пространство или на onboarding.
8. **Найдено сценарием А:** маршрут пространства брал устаревший кэш списка пространств и
   показывал «не найдено» сразу после создания. Теперь незнакомый slug перепроверяется.
