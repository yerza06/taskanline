# Этап 1. Аутентификация и пользователи — Implementation Plan

> **Для исполнителя:** реализовывать по `superpowers:subagent-driven-development` или
> `superpowers:executing-plans`, задача за задачей. Шаги отмечены чекбоксами.

## Context

Этап 0 «Фундамент» закрыт 2026-09-18: приложение поднимается, миграции накатываются, тесты и
линтеры зелёные, но в системе нет ни одной бизнес-сущности и ни одной таблицы. Следующий этап
roadmap — «Аутентификация и пользователи». Он нужен не сам по себе: на нём появляется `Principal`,
на который опирается **весь** последующий слой авторизации (этап 2 и дальше). Пока `Principal`
нет, ни один защищённый эндпоинт написать нельзя.

Результат этапа: человек регистрируется и входит (cookie-сессия), агент получает PAT и ходит им в
API, первый зарегистрировавшийся становится `superadmin`, а потеря доступа лечится
management-командой.

**Спецификации (источник правды):**
- `docs/superpowers/specs/2026-09-16-taskanline-roadmap.md` — «Этап 1», чеклист и критерий готовности
- `docs/superpowers/specs/2026-09-16-taskanline-architecture.md` — §3.2 слои модуля, §3.3 Principal,
  §3.6 контракт API, §3.8 карта эндпоинтов
- `docs/superpowers/specs/2026-09-16-taskanline-data-model.md` — §2 `users`, §5 `api_tokens` /
  `refresh_tokens`, §6.4 scope, §7 порядок миграций

**Решения, принятые сверх спеки** (при реализации внести в спеки тем же изменением, что и код):
1. `POST /auth/register` сразу выдаёт пару токенов в cookie — регистрация логинит.
2. CSRF-заголовок `X-Requested-With` включается уже на этапе 1 (в чеклисте roadmap пункта нет —
   добавить его в roadmap).
3. Новая группа настроек `AUTH__`; `SECURITY__` остаётся только про секреты.
4. Вход неактивного пользователя (`is_active = false`) отвечает `401 invalid_credentials`, а не
   отдельным кодом: иначе по ответу можно перебором выяснить, какие email зарегистрированы.
5. `users.last_seen_at` обновляется при входе, а не на каждом запросе — лишняя запись на каждый
   вызов API не окупается.

## Global Constraints

- Python 3.13, uv-workspace. Бэкенд — FastAPI + SQLAlchemy 2.0 async + asyncpg + Alembic.
- Комментарии, докстроки, сообщения коммитов — на русском; имена в коде и тестах — на английском.
- Ветка: от `dev`, называется `feat/auth`. В `dev` и `main` не вливать — это решение человека.
- Слои модуля неизменны: `models.py` / `schemas.py` / `repository.py` / `service.py` / `router.py`.
  Роутер не трогает репозиторий; сервис не трогает чужой репозиторий.
- Формат ошибки — только `{"error": {"code", "message", "details"}}` через `ApiError` из
  `app/core/errors.py`.
- Все прикладные пути — с префиксом `/api/v1`. `/health` остаётся вне префикса.
- Redis нет. Rate limiting — в памяти процесса, за интерфейсом `RateLimiter`.
- Миграции применяются отдельной командой, не из кода. Ревизия — строго `0001_users_auth`.
- Enum'ы в БД — `VARCHAR` + `CHECK`, в Python — `StrEnum`. Первичные ключи — UUIDv7 из `uuid6`.
- TDD: тест пишется первым и падает по нужной причине. Коммит после каждой задачи.
- Новая настройка добавляется в группу и обязательно в `.env.example` (иначе падает
  `TestEnvExample`).
- Отсутствие доступа → 404; 403 только когда объект виден, но действие запрещено.

_hasher = PasswordHasher()          # argon2-cffi: Type.ID по умолчанию

def _base62(raw: bytes, length: int) -> str:
    number = int.from_bytes(raw, "big")
    chars: list[str] = []
    while number:
        number, remainder = divmod(number, 62)
        chars.append(_ALPHABET[remainder])
    return "".join(reversed(chars)).rjust(length, _ALPHABET[0])


def generate_pat() -> str:

### Task 3: `core/rate_limit.py`

**Files:**
- Create: `backend/app/core/rate_limit.py`, `backend/tests/test_rate_limit.py`

**Interfaces — Produces:**

```python
@dataclass(frozen=True)
class RateLimitResult:
    allowed: bool
    retry_after: int          # секунды до следующей попытки, 0 если allowed

class RateLimiter(Protocol):
    def hit(self, key: str, *, limit: int, window_seconds: int) -> RateLimitResult: ...

class InMemoryRateLimiter:     # реализация Protocol
    def __init__(self, *, clock: Callable[[], float] = time.monotonic) -> None: ...
    def hit(self, key: str, *, limit: int, window_seconds: int) -> RateLimitResult: ...
    def reset(self) -> None: ...
```

Интерфейс синхронный: в памяти процесса await нечего ждать, а `async` здесь только мешал бы
подменить реализацию на Redis-версию этапа 9 — та всё равно будет другой абстракцией с очередью.

- [ ] **Шаг 1.** Тесты (чистые, без БД и HTTP), `clock` подменяется списком значений:

```python
def test_allows_up_to_limit():
    limiter = InMemoryRateLimiter(clock=lambda: 0.0)

    results = [limiter.hit("ip", limit=3, window_seconds=60) for _ in range(3)]

    assert all(result.allowed for result in results)


def test_blocks_over_limit_and_reports_retry_after():
    now = 0.0
    limiter = InMemoryRateLimiter(clock=lambda: now)
    for _ in range(3):
        limiter.hit("ip", limit=3, window_seconds=60)

    result = limiter.hit("ip", limit=3, window_seconds=60)

    assert result.allowed is False
    assert result.retry_after == 60


def test_window_slides():
    current = {"t": 0.0}
    limiter = InMemoryRateLimiter(clock=lambda: current["t"])
    for _ in range(3):
        limiter.hit("ip", limit=3, window_seconds=60)

    current["t"] = 61.0

    assert limiter.hit("ip", limit=3, window_seconds=60).allowed is True


def test_keys_are_independent():
    limiter = InMemoryRateLimiter(clock=lambda: 0.0)
    for _ in range(3):
        limiter.hit("a", limit=3, window_seconds=60)

    assert limiter.hit("b", limit=3, window_seconds=60).allowed is True


def test_old_keys_do_not_leak():
    """Окно, из которого всё вышло, не должно оставлять пустую очередь навсегда."""
    current = {"t": 0.0}
    limiter = InMemoryRateLimiter(clock=lambda: current["t"])
    limiter.hit("a", limit=3, window_seconds=60)
    current["t"] = 1000.0

    limiter.hit("b", limit=3, window_seconds=60)

    assert "a" not in limiter._hits
```

Порядок резолвинга в `get_principal`:

### Task 9: CSRF-заголовок на мутациях с cookie-сессией

**Files:**
- Create: `backend/app/core/csrf.py`, `backend/tests/test_csrf.py`
- Modify: `backend/app/main.py`, `docs/superpowers/specs/…roadmap.md`

Правило (архитектура §3.3): метод изменяющий (`POST`, `PATCH`, `PUT`, `DELETE`), запрос несёт
cookie сессии и **не** несёт `Authorization` → обязателен заголовок
`X-Requested-With: XMLHttpRequest`, иначе `403 csrf_required`. Запросы без cookie (регистрация,

**Критерий готовности этапа (roadmap) — вручную, на чистой базе**

```bash
uv run python -m app.main &

# 1. Регистрация: первый пользователь → superadmin, cookie выставлены
curl -s -c /tmp/tkl.jar -H 'X-Requested-With: XMLHttpRequest' \
     -H 'Content-Type: application/json' \
     -d '{"email":"ivan@example.com","password":"correct horse battery","full_name":"Иван"}' \
     http://localhost:8000/api/v1/auth/register | jq .user.role      # → "superadmin"

# 2. Выпуск PAT на чтение и на запись
curl -s -b /tmp/tkl.jar -H 'X-Requested-With: XMLHttpRequest' \
     -H 'Content-Type: application/json' -d '{"name":"agent","scope":"read"}' \
     http://localhost:8000/api/v1/me/tokens | jq -r .token           # → tkl_…

# 3. GET /me этим токеном
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/v1/me | jq .email

# 4. Токен со scope=read на мутации
curl -s -o /dev/null -w '%{http_code}\n' -X PATCH \
     -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"full_name":"Новое имя"}' http://localhost:8000/api/v1/me   # → 403

# 5. Ротация и выход
curl -s -b /tmp/tkl.jar -c /tmp/tkl.jar -X POST -H 'X-Requested-With: XMLHttpRequest' \
     http://localhost:8000/api/v1/auth/refresh | jq .user.email
curl -s -o /dev/null -w '%{http_code}\n' -b /tmp/tkl.jar -X POST \
     -H 'X-Requested-With: XMLHttpRequest' http://localhost:8000/api/v1/auth/logout  # → 204
```

Этап считается закрытым, когда шаг 1 отдаёт `superadmin`, шаг 3 — email пользователя, шаг 4 —
ровно `403` с кодом `insufficient_scope`, а `uv run pytest` зелёный.
