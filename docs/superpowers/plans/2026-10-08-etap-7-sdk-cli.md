# Этап 7. SDK и CLI — Implementation Plan

> **Для исполнителя:** реализовывать задача за задачей, по TDD. Шаги отмечены чекбоксами (`- [ ]`).

**Goal:** `taskanline_sdk` — типизированный асинхронный клиент API; `tkl` — CLI для агентов
поверх него. Готово, когда проходит сценарий Г: агент через `tkl` находит свои задачи, берёт одну
в работу, комментирует и закрывает, а история задачи показывает токен.

**Architecture:** SDK — httpx + Pydantic, ресурсы по доменам (`client.tasks`, `client.views`, …),
типизированные исключения, ретраи, пагинация асинхронным итератором. CLI — Typer, асинхронные
команды под одним `run()`; разбор мини-DSL фильтров переводит строку в грамматику фильтров view
(§4 модели данных), а имена (ключ команды, имя статуса, метки, email) разрешает запросами к API.
Списки задач CLI идут через новый `POST /views/query` — несохранённый view.

**Spec:** `…-cli-spec.md` (весь), `…-architecture.md` (§5), `…-vision.md` (сценарий Г),
`…-roadmap.md` («Этап 7»).

## Решения сверх спеки (внести в спеки в последней задаче)

1. **`POST /views/query`** — выполнение несохранённого view: тело `{workspace_id, filters,
   sort_by, sort_direction, group_by, group, cursor, limit}`, ответ как у
   `GET /views/{id}/tasks` без `view_id`. Права — чтение workspace, токен `read` годится. Так у
   CLI и views одна грамматика и один транслятор, а у `GET /tasks` не появляется второй язык
   фильтров.
2. **Грамматика фильтров расширена:** `parent_id` (`in`/`nin`) и `is_null`/`not_null` для
   `project_id`, `assignee_id` — без этого DSL не выразит `assignee:null` и `parent:ENG-1`.
3. **Исключения SDK:** `ApiError` — общий предок; `AuthenticationError` (401),
   `PermissionDeniedError` (403 — не `PermissionError`, чтобы не затенять встроенное),
   `NotFoundError`, `ValidationError` (400, 422), `ConflictError`, `RateLimitError`
   (`retry_after`), `ServerError` (5xx), `NetworkError` (сеть и таймаут).
4. **Ретраи:** 429 — всегда (запрос не исполнялся), с учётом `Retry-After`; 5xx и сетевые
   ошибки — только для безопасных методов и запросов с `Idempotency-Key`. `tasks.create`
   ставит `Idempotency-Key` сам, поэтому повтор не создаёт дубль.
5. **Пакет CLI — `taskanline_cli`**, а не `cli/src/tkl/` из спеки: пакет уже заведён под этим
   именем на этапе 0; бинарь — `tkl`.
6. **Ошибка использования — код 1.** Click по умолчанию выходит с 2; `main()` перехватывает
   `UsageError` сам.
7. **DSL → грамматика view.** `me` → `@me`, `@week` → `@start_of_week`, приоритеты словами
   (`urgent` … `low`, `none`) и числами; `a,!b` вперемешку — ошибка разбора.
8. **`url` задачи** — `{web_url}/{KEY}`, `web_url` профиля по умолчанию равен `api_url`.

Добавлено по ходу реализации:

9. **Методы SDK — `all()` и `page()`**, а не `list()`: имя `list` у метода затеняло бы встроенный
   `list` в аннотациях следующих методов класса (аннотации в 3.13 вычисляются сразу).
10. **Typer 0.27 вшивает свою копию Click:** опции вызова хранятся в модуле `context`, а
    `main()` запускает команду в standalone-режиме и переводит код 2 Click в 1.
11. **Глобальные опции принимаются в любом месте строки** — `main()` переносит их вперёд.
12. **`nin` по `parent_id`** включает задачи без родителя — как у других необязательных полей.
